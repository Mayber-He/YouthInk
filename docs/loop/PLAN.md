# 小说生成链路修复 · 循环计划

当前分支原无本文件。总规则沿用 `PROGRESS.md` 的工作约定及本次用户要求；T1–T7 的历史结果保留在 `PROGRESS.md`，本文件记录后续 T8–T12，不重建历史计划。

## 总规则

- 原约定每轮一个任务；用户已确认本次连续完成 T8–T12，不逐项停下确认。每项仍独立验证、更新进度并创建一个 commit。
- 每个任务先核对当前代码和数据证据，再做最小范围修改，不顺手处理其他任务。
- 不调用真实 LLM；模型行为只用 mock、固定样本及用户已有真实输出验证。
- 不修改现有小说数据。调查数据库必须只读；测试使用隔离的临时数据库，不启动可能对真实库执行迁移的应用。
- schema 改动必须向后兼容（只加列/加表、带默认值）；沿用改前备份要求，但不得据此在真实小说库自动执行迁移或修复。
- 补充新增行为的回归测试，运行相关测试及全量测试；前端改动检查类型及相关交互。区分已有失败与新增失败，不把有失败的全量结果写成全部通过。
- 每轮结束更新 `docs/loop/PROGRESS.md`，记录改动、验证命令与结果、局限和需要用户人工确认的事项，并创建一个 commit。
- 汇报每个已执行任务的改动、验证结果与人工确认事项；未执行任务保持待执行，不以计划登记代替实现完成。
