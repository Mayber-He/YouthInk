## HTTPX 超时含义与 40 秒评估

当前调用是 `httpx.AsyncClient(timeout=timeout_sec).post(...)`、`stream=False`。单值设置 connect/read/write/pool 各阶段的超时；`ReadTimeout` 表示等待响应头或下一块响应数据超过读取空闲上限，**即使非流式也不是整次响应的总墙钟时限**。客户端会收完整个响应体才返回；若上游生成完 JSON 才发送首块，读取超时在实际体验上接近等待完整结果超时。原代码首次和重试均重新读取同一配置，默认都是 40 秒，没有额外总等待截止时间。

依据：[HTTPX 官方超时文档](https://www.python-httpx.org/advanced/timeouts/)，以及本地 `backend/app/services/llm/client.py` 的非流式实现。

7 次成功调用输出 1525–3235 字符，耗时 24.765–71.991 秒，中位数 39.050 秒；3/7 超过 40 秒。可见输出折算吞吐 39.1–85.1 字符/秒，中位数约 44.9 字符/秒，粗略生成 1500–3200 字符约需 33–71 秒。该比率包含首字等待、上游排队、输入处理及可能的隐藏推理，并非纯解码速度。日志 output_tokens 为 3935–14014，远高于可见 JSON 字符数，可能包含推理或提供商的其他计数，不能凭此精确估计生成速度。结论：40 秒偏短，已有成功样本直接支持，不能保证恢复 90 秒后永不超时。

## 最小修复与取值

- 默认首次 HTTP 空闲超时恢复 90 秒，`YOUTHINK_BOUNDARY_TIMEOUT_SEC` 仍可覆盖（5–120 秒，非法值回退，越界夹紧）。
- 重试 HTTP 空闲超时 = `min(120, 首次配置 × 1.5)`；如 30→45、60→90、90→120。120 秒配置已达上限，不再增长。
- 增加单调时钟 **150 秒共享等待预算**，每次通过 `asyncio.wait_for` 设置墙钟上限 `min(该次超时, 剩余预算)`，超时取消请求。默认首次若耗满 90 秒，重试实际最多剩 60 秒；首次很快失败则重试可获 120 秒。90 秒比已观测成功最长约 72 秒留出约 18 秒余量；150 秒采用用户给出的 2.5 分钟总预算。这样同时保留默认 90 秒并将两次总等待限制在 2.5 分钟内。异步取消和同步解析/日志收尾可能有少量调度开销，并非操作系统硬实时保证。
- 提示词要求 established/repeated_events/avoid 各最多 5 条，statement/evidence_quote/avoid 每条最多 30 字，next_step 最多 80 字，不展开推理。合法 JSON 不因冗长被拒绝：先对完整引用做原有真实性校验。完整模式随后截短字段再注入；若超长判断句带否定/条件而不宜截短，则保守省略该项，不报错、不重试；瘦身模式保留完整判断句通过原有否定检查和短语抽取，最终只注入有数量/长度上限的短语与接续提示，避免截短掩盖虚构引用后缀或否定词。
- 不添加很小的 `max_tokens` 硬上限：上游可能将隐藏推理计入额度，容易把 JSON 截成无效数据、反而触发重试。提示词压缩影响真实模型耗时的幅度仍待用户后续实测；本次不调用 LLM。
- 降级提示含总耗时、各次原因及各次耗时，保留重试状态；移除服务层原先 120 字截断，避免诊断末尾被吞。每次 warning 还记录 chapter_id/scene_id、HTTP 空闲上限、实际等待额度。成功的检查日志新增 scene_id 关联。失败仍不会额外写小说库；失败排查使用应用 warning 与 UI 提示。

## 流式读取评估（本次不迁移）

流式可行，但改变的是上游 `stream=true` 发包节奏，HTTPX 的读取计时规则本来就按块空闲计算。优点是模型若及时发送 token 或心跳，可减少长生成的无数据间隔；缺点是首块前的推理/排队仍可超时，代理可能缓冲，心跳可能持续刷新空闲超时却不产生有效 JSON，仍需独立总预算。结构化检查也必须收齐 JSON 后才能解析，不能拿半截结果指导正文。

最小后续范围：在 `llm/client.py` 增加聚合 SSE 内容的 completion 适配（不复用面向前端 meta/delta/done 的协议作为内部 JSON）；仅衔接检查选择该路径；保留 usage/finish_reason 和成功/失败日志语义；新增首块超时、块间超时、心跳、断流、截断 JSON、取消与总预算测试。无需修改正文 SSE 或前端接口。本次按请求只评估，不直接大改；先采用超时预算与短输出方案。
