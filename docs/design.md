## 1. 产品概述

### 1.1 定位

面向青春小说创作的 Windows 桌面工作台。用户填写大致内容后，系统依次生成世界观、人物、地点、主线剧情、分卷目录、章节细纲和正文，并通过记忆系统保证**百万字级**长篇写作的设定一致性。

### 1.2 基本约束

| 项目 | 结论 |
|---|---|
| 目标平台 | 仅 Windows（Win10 / Win11） |
| 使用模式 | 单机单用户，无账号、无云同步、无协作 |
| 大模型 | 云端 API，统一使用 **OpenAI 兼容格式** |
| Embedding | 本地模型，首次启动时下载 |
| 目标篇幅 | 百万字级（约 400 章 × 2500 字） |
| 交付形式 | NSIS 安装包（`setup.exe`） |

### 1.3 核心原则

- **生成 → 编辑 → 锁定**：每一步产出都可以人工修改和锁定，下游以锁定内容为准。
- **AI 抽取的记忆按信任模式处理**：信任模式默认开启，事实和伏笔暗示自动确认，其他类型默认待人工确认，避免一次幻觉写入记忆后被不断放大。
- **定稿才入库**：草稿阶段反复修改不会污染记忆。
- **上下文透明**：每次生成前，作者能看到并调整实际注入给模型的内容。

## 2. 技术架构

### 2.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Tauri 2 | 使用系统 WebView2，内置 sidecar 管理 |
| 前端 | React + TypeScript | |
| UI | shadcn/ui + Tailwind CSS | |
| 编辑器 | TipTap | 富文本、中文输入法稳定 |
| 前端状态 | Zustand + TanStack Query | |
| 后端 | Python + FastAPI | 以 sidecar 形式运行，监听 `127.0.0.1` 随机端口 |
| 业务数据 | SQLite | |
| 向量库 | LanceDB | 嵌入式，支持元数据过滤 |
| 全文检索 | SQLite FTS5 + jieba 预分词 | 解决中文分词问题 |
| Embedding | bge-m3（ONNX int8，约 600MB）+ onnxruntime | 不依赖 PyTorch |
| 重排（v0.2） | bge-reranker-v2-m3（ONNX） | |
| 打包 | PyInstaller（onedir）→ Tauri sidecar → NSIS | |

### 2.2 进程结构

```
┌──────────────────────────────┐
│ Tauri 主进程（YouthInk.exe）   │
│  └─ WebView2：React 前端       │
└──────────────┬───────────────┘
               │ 启动 / 退出管理（sidecar）
               │ HTTP + SSE（流式输出）
┌──────────────▼───────────────┐
│ Python sidecar（FastAPI）      │
│  ├─ LLM 调度（OpenAI 兼容）     │
│  ├─ 上下文组装 / RAG            │
│  ├─ 记忆抽取与入库               │
│  ├─ Embedding（onnxruntime）    │
│  └─ SQLite / LanceDB 读写       │
└──────────────────────────────┘
```

### 2.3 LLM 接入

- **模型档案**：每个档案包含 `base_url`、`api_key`、`model`，可以添加多个。
- **按任务分配模型**：

| 任务类别 | 推荐档次 |
|---|---|
| 正文写作、润色 | 最强模型 |
| 大纲、人设、世界观 | 强模型 |
| 摘要、抽取、状态更新、JSON 修复 | 便宜快速的模型 |

- 流式输出通过 SSE 推送到前端，支持中途停止。
- API Key 存入 Windows 凭据管理器（`keyring`），不明文落盘。
- 每次调用都记录 token 消耗。

### 2.4 Embedding 模型下载

- 存放位置：`%APPDATA%/YouthInk/models/`
- 下载源：ModelScope / HF 镜像 / HuggingFace，可切换
- 支持断点续传、文件校验、手动导入
- 模型未就绪时可以正常进行立项和设定，只有记忆入库需要等待

### 2.5 作品存储

每部作品一个独立目录：

```
<作品目录>/
├─ novel.db        # SQLite：全部业务数据
├─ vectors/        # LanceDB 向量索引
└─ backups/        # 自动备份
```

## 3. MVP 范围与里程碑

### 3.1 版本规划

**v0.1（MVP）**

| 模块 | 内容 |
|---|---|
| 基础设施 | Tauri + sidecar 启停、模型档案、任务分配、Embedding 下载 |
| 作品管理 | 新建、打开、删除，自动备份 |
| 立项 | 立项表单（含感情线结局、成长线结局） |
| 设定生成 | 世界观、人物卡、地点：生成、编辑、锁定 |
| 剧情和目录 | 主线 → 分卷 → 情节弧 → 章节（按弧滚动生成） |
| 章节细纲 | 场景节拍 |
| 正文写作 | 逐场景流式生成、停止、重写、选中改写，自动保存，历史版本 |
| 记忆闭环 | 场景入库、分层摘要、事实抽取、人物状态、认知追踪、关系、伏笔、待确认队列（含信任模式） |
| 上下文组装 | 按优先级和 token 预算拼装，前端可预览和调整 |
| 检索 | 元数据过滤 + 向量 + FTS5，RRF 融合 |
| AI 味检测 | 本地词表和正则扫描，编辑器内标记 |
| Prompt | 模板开放编辑，可恢复默认 |
| 导出 | TXT / Markdown |

**v0.2**
- 自动一致性检查（与设定库、状态比对）
- 重排模型
- 时间线、关系图谱可视化
- 修改前文后自动重算后续状态
- 风格模板库扩充
- token 消耗统计面板

**v0.3 及以后**
- EPUB / DOCX 导出
- 一键连续写多章
- 代码签名、自动更新
- 灵感库、素材库

### 3.2 里程碑

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| M1 骨架 | 壳 + sidecar + 配置 + 作品管理 + **打包流水线** | 能打出可安装的 exe，并调通一次 LLM |
| M2 设定链路 | 立项 → 世界观 → 人物 → 地点 → 主线 → 目录 | 从一句话梗概生成完整目录，可编辑、可锁定 |
| M3 写作 | 细纲 + 编辑器 + 流式生成 | 能顺畅写完一章 |
| M4 记忆闭环 | 入库、摘要、抽取、状态、认知、伏笔、检索、上下文组装 | 连续写 30 章，人物状态正确延续 |
| M5 压测 | 脚本模拟生成 100 章以上 | 召回准确、矛盾率可接受 |

> 打包流水线放在 M1，尽早暴露 PyInstaller、onnxruntime、sidecar 的打包问题。

## 4. 数据模型

> 以下为逻辑模型，具体表结构在开发阶段细化。

### 4.1 作品（立项）

| 字段 | 说明 |
|---|---|
| 书名 | |
| 题材 | 校园、都市青春、成长、暗恋…… |
| 基调 | 清新、治愈、虐、搞笑、现实向 |
| 叙事视角 | 第一人称 / 第三人称限知 / 第三人称全知 / 多视角轮换 |
| 主角概念 | |
| 故事梗概 | 用户填写的大致内容 |
| 目标字数、预计章数、单章字数 | |
| 感情线结局 | HE / BE / 开放式 / 遗憾向 / 自定义 |
| 成长线结局 | HE / BE / 开放式 / 遗憾向 / 自定义 |
| 结局补充说明 | |
| 文风补充说明 | |
| 风格模板 | 关联风格模板（见第 7 节） |

### 4.2 结构层级

```
作品 → 卷 → 情节弧 → 章节 → 场景
```

| 实体 | 关键字段 |
|---|---|
| 卷 | 序号、标题、梗概、目标 |
| 情节弧 | 序号、标题、目标、起止章节、核心冲突 |
| 章节 | 排序号、标题、梗概、状态（未开始 / 细纲 / 草稿 / 定稿）、字数、故事内时间 |
| 场景 | 所属章节、序号、节拍描述、视角人物、地点、出场人物、故事内时间、目标字数 |
| 章节版本 | 正文、版本号、来源（AI / 手动）、创建时间 |

章节的**排序号**与显示的"第几章"分离，插入章节时不影响其他引用。

### 4.3 设定实体

**世界观条目**：分类（时代背景、城市、学校、规则制度、流行文化、专有名词）、内容、是否锁定。

**人物卡**（静态信息）：

| 字段 | 说明 |
|---|---|
| 姓名、别名和昵称 | 别名用于检索时的实体识别 |
| 角色定位 | 女主、男主、重要配角、配角、路人 |
| 性别、初始年龄或年级 | |
| 外貌特征 | 作为外貌的初始基准 |
| 性格内核 | |
| 说话风格、口头禅 | |
| 家庭背景、过往经历 | |
| 人物弧光设计 | |
| 是否锁定 | |

**地点**：名称、别名、类型、描述、感官细节（声音、气味、光线）、关联人物、是否锁定。

**主线剧情**：核心冲突、感情线走向、成长线走向、关键转折点、是否锁定。

### 4.4 随时间变化的状态

采用**变更记录**的方式：只记录"第 N 章某字段变成了什么"。查询第 N 章的状态时，取每个字段在该章及之前最新的一条记录。

所有变更记录都包含：来源章节、来源场景、原文引用片段、确认状态（待确认 / 已确认 / 已废弃）。

**人物状态变更**

| 字段 | 示例 |
|---|---|
| 当前位置或所处环境 | 转学到了三中 |
| 身体状态 | 脚踝扭伤 |
| 情绪和心理状态 | 因为误会对男主冷淡 |
| 当前目标 | 想考上美院 |
| 身份变化 | 当上了班长 |
| 持有的重要物品 | 那封没送出去的信 |
| 外貌变化 | 剪了短发、戴上眼镜 |

写作时注入的外貌 = 人物卡基准外貌 + 最新外貌变化。

**认知记录（谁知道什么）**

| 字段 | 说明 |
|---|---|
| 秘密或事实 | "林夏暗恋陆川" |
| 知情人物 | |
| 得知章节、得知方式 | |

用于防止"人物不知道某件事却在言行中提及"。

**人物关系变更**：人物 A、人物 B、关系类型（同学、朋友、暗恋、恋人、敌对……）、亲密度、公开程度（公开 / 仅双方知道 / 单方面）、变化原因。

**时间线**：故事内时间（如"高一上学期期中前一周"）、事件、关联章节。

**伏笔台账**：描述、埋下章节、计划回收区间、状态（埋下 / 暗示 / 已回收 / 已放弃）、相关章节。

### 4.5 记忆与检索

**事实库**

| 字段 | 说明 |
|---|---|
| 内容 | "林夏对芒果过敏" |
| 类型 | 人物属性、事件、物品、约定、地点细节…… |
| 关联实体 | 人物、地点 |
| 来源 | 章节、场景、原文引用片段 |
| 状态 | 待确认 → 已确认 → 已锁定 / 已废弃 |

**摘要**：层级（章 / 弧 / 卷 / 全书）、关联 ID、内容、是否过期。

**向量分块（LanceDB）**

| 字段 | 用途 |
|---|---|
| 文本、向量 | 语义检索 |
| 章节排序号、场景 ID | 定位、范围过滤 |
| 出场人物 ID 列表、地点 ID | 元数据过滤 |
| 故事内时间 | 时间过滤 |
| Embedding 模型标识 | 换模型时提示重建索引 |

分块以场景为单位，过长的场景按 500~800 字切分，相邻块保留少量重叠。

**生成记录**：任务类型、模型、模板版本、完整 prompt、输出、token 数、耗时。

## 5. 记忆系统（防幻觉）

### 5.1 三层记忆

| 层 | 内容 | 使用方式 |
|---|---|---|
| 结构化设定 | 世界观、人物卡、地点、状态、认知、关系、伏笔 | SQLite 精确查询，作为硬约束注入 |
| 分层摘要 | 全书 → 卷 → 弧 → 章 | 让模型知道"写到哪里了" |
| 向量检索 | 已定稿正文的分块 | 召回历史细节 |

### 5.2 分层摘要规格

| 层级 | 长度 |
|---|---|
| 章摘要 | 约 300 字 |
| 弧摘要 | 约 800 字 |
| 卷摘要 | 约 1500 字 |
| 全书梗概 | 约 2000 字 |

### 5.3 上下文组装（每章约 20k~40k token 预算）

| 优先级 | 内容 | 来源 |
|---|---|---|
| 必带 | 风格要求、本章细纲 | 设定库 |
| 必带 | 出场人物当前状态 + 人物卡 | SQLite |
| 必带 | 出场人物的认知约束 | SQLite |
| 必带 | 本章地点、故事内时间 | SQLite |
| 必带 | 全书梗概 + 已完结卷的卷摘要 + 当前卷的弧摘要 + 最近 5~10 章的章摘要 + 上一章全文 | SQLite |
| 必带 | 本章计划推进或回收的伏笔 | 伏笔台账 |
| 补充 | 相关历史片段 | 检索 |

**检索流程**：按出场人物、地点、章节范围做元数据过滤 → 向量检索 + FTS5 关键词检索 → RRF 融合 → （v0.2）重排 → 按预算截取。

前端在生成前展示组装结果，用户可以勾选、取消或手动添加参考。

### 5.4 定稿后的记忆闭环

```
点击定稿
  → 场景切分 → 写入向量库 + FTS5
  → 生成章摘要 → 必要时更新弧、卷摘要
  → 抽取：事实 / 人物状态变更 / 认知 / 关系 / 伏笔（均附原文引用）
  → 进入待确认队列
  → （v0.2）一致性检查
  → 确认后写回，成为后续写作的约束
```

### 5.5 信任模式

信任模式默认开启，按下表处理抽取结果；关闭后，所有抽取结果均需人工确认。

| 类型 | 默认处理 |
|---|---|
| 事实 | 自动确认 |
| 伏笔：暗示 | 自动确认 |
| 人物状态变更 | 人工确认 |
| 关系变更 | 人工确认 |
| 认知变更 | 人工确认 |
| 伏笔：埋下、回收 | 人工确认 |

用户可以在设置中调整。

### 5.6 前文修改

修改已定稿章节后，相关摘要标记为"过期"，提示用户重新生成。（v0.2：自动重算后续状态）

## 6. 界面设计

### 6.1 页面结构

```
启动页（作品列表）
  └─ 作品工作台
       ├─ 立项
       ├─ 世界观
       ├─ 人物
       ├─ 地点
       ├─ 主线剧情
       ├─ 目录（卷 / 弧 / 章）
       ├─ 写作
       ├─ 伏笔台账
       └─ 待确认队列
全局设置（模型档案、任务分配、Embedding、Prompt 模板、信任模式、存储路径）
```

**首次启动向导**：配置 API → 测试连接 → 下载 Embedding 模型（可在后台进行）。

### 6.2 工作台三栏布局

```
┌──────────┬──────────────────────────────┬──────────────┐
│ 左栏      │ 主区域                        │ 右栏（可折叠） │
│ 导航 +    │                              │ 上下文面板    │
│ 目录树    │                              │              │
├──────────┴──────────────────────────────┴──────────────┤
│ 状态栏：字数 / 当前模型 / token / 后台任务 / 自动保存      │
└────────────────────────────────────────────────────────┘
```

- 左栏目录树用图标表示章节状态，支持拖拽排序
- 待确认队列显示数字角标

### 6.3 设定类页面

- 卡片列表 + 详情编辑
- 每张卡片可以单独锁定；"AI 生成全部"只重新生成未锁定的卡片
- 单个字段可以让 AI 按修改意见重写
- 人物详情页带**状态时间轴**，可以查看任意章节时的状态、关系和认知

### 6.4 写作页

- 顶部：章节标题、状态、可折叠的场景节拍
- 中间：TipTap 编辑器
- 右栏三个标签页：
  - **细纲**：场景节拍编辑和生成
  - **上下文**：生成前预览注入内容（各部分 token 数），可勾选调整
  - **记忆**：定稿后的抽取结果，可直接确认
- 编辑器交互：
  - 选中文字后：改写、扩写、缩写、润色、换成某人的语气
  - 细纲中用 `@人物`、`@地点` 关联实体
  - AI 味检测结果以波浪线标记，可一键重写该句
  - 专注模式：隐藏左右栏

### 6.5 待确认队列

- 按类型和章节筛选，支持批量确认
- 每一条可以确认、编辑、废弃
- 点击跳转到原文位置并高亮

### 6.6 视觉

- 浅色 / 深色主题
- 中文排版：首行缩进、行高、可选字体字号

## 7. Prompt 体系与风格模板

### 7.1 分层结构

按"稳定 → 易变"排列，以命中服务商的前缀缓存：

```
① 系统角色
② 风格模板
③ 作品核心设定（全书梗概、世界观要点、结局方向）
④ 动态上下文（摘要、人物状态、认知约束、检索片段）
⑤ 任务指令
⑥ 输出格式要求
```

### 7.2 任务模板

| 分类 | 任务 | 输出 |
|---|---|---|
| 设定 | 生成世界观、人物、地点、主线 | JSON |
| 设定 | 单项重写或补充 | JSON |
| 结构 | 分卷、情节弧、章节目录 | JSON |

**模板管理**：
- 内置模板以文件形式随程序发布
- **开放给用户编辑**：在设置中查看和覆盖，覆盖后保存为用户版本，可一键恢复默认
- 使用 `{{变量名}}` 占位，由后端渲染
- 生成记录中保存模板版本

### 7.3 风格模板

| 维度 | 选项 |
|---|---|
| 叙事视角 | 第一人称 / 第三人称限知 / 多视角轮换 |
| 时态与语感 | 当下进行感 / 回忆追述感 |
| 文风基调 | 清新治愈、细腻文艺、轻松搞笑、虐心、现实向 |
| 句式偏好 | 短句为主 / 长短交错 / 偏重长句 |
| 对话比例 | 少 / 适中 / 多 |
| 描写侧重 | 心理、环境氛围、动作细节、对话推进 |
| 节奏 | 慢热细腻 / 紧凑推进 |
| 示例段落 | 1~3 段文风参考（限制篇幅，仅作文风参考） |
| 禁用表达 | 用户自定义 + 内置清单 |

**内置预设**：清新校园、细腻暗恋、轻松欢脱、青春疼痛。

### 7.4 减少 AI 味

1. **禁用和限频清单**（可编辑）：如「不由得」「嘴角勾起一抹弧度」「心中五味杂陈」「眼中闪过一丝」；章末升华总结、滥用排比等结构套路。
2. **正向要求**：用具体细节代替抽象情绪；对话符合人物说话风格；不在章末替读者点题。
3. **生成后检测（MVP）**：本地词表 + 正则扫描，不消耗 API 调用。

### 7.5 正文生成策略

- **默认逐场景生成**：生成场景 N 时带上本章完整细纲和前一场景全文
- 可切换为整章生成
- 字数控制：按场景分配目标字数，生成后检查；不足时提供扩写，过长时提示，不自动截断

### 7.6 结构化输出

- 每个 JSON 任务对应一个 Pydantic Schema，prompt 中附 Schema 和示例
- 不依赖服务商特有的 `json_schema` 模式
- 解析降级流程：直接解析 → 提取代码块 → 宽松修复 → 便宜模型修复 → 最多重试 2 次 → 失败后向用户展示原文
- 抽取类任务要求每条结果附带原文引用片段

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| Python sidecar 被杀毒软件误报 | onedir 模式、代码签名，必要时改用 Nuitka |
| 首次模型下载失败 | 镜像源 + 断点续传 + 手动导入 |
| 安装包体积过大 | 不引入 PyTorch，使用 onnxruntime；模型不打包 |
| 抽取或一致性检查成本高 | 使用便宜模型，只处理本章涉及的实体 |
| 一次生成大量细纲质量下降 | 按情节弧滚动生成 |
| 修改前文导致状态链断裂 | 标记过期并提示；v0.2 提供自动重算 |
| 各服务商 OpenAI 兼容程度不一 | 只使用基础的 chat completions + 流式输出，JSON 靠 prompt 约束和校验 |
| 换 Embedding 模型导致索引失效 | 索引记录模型标识，切换时提示重建 |
